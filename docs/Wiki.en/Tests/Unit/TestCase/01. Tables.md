## Scope

This table maps the existing TestCaseTest checks for adding, confining, including, and excluding axes, and for testing whether conditions can be confined.
The nine contract groups correspond to 27 existing NUnit methods, each a single case without parameters.

## States and actions

| ID | State/input | Action | Current verification | Cases |
| --- | --- | --- | --- | --- |
| UT01 | No condition axes or existing axes | Append | Add a new inclusion axis and preserve existing axis values | 2 |
| UT02 | Existing axis or end position | Confine | Replace the first/last axis with a single included value or add a new axis | 3 |
| UT03 | Undefined/inclusion/exclusion axis | Include | Create an inclusion axis, union inclusion sets, or remove allowed values from an exclusion set | 3 |
| UT04 | Undefined/exclusion/inclusion axis | Exclude | Create an exclusion axis, union exclusion sets, or remove prohibited values from an inclusion set | 3 |
| UT05 | Inclusion or undefined axis | Single-value Confineable out overload | Included value produces a single-value inclusion result, absent value returns false, undefined axis expands | 3 |
| UT06 | Exclusion or undefined axis | Single-value Confineable out overload | Nonexcluded value produces a single-value inclusion result, excluded value returns false, undefined axis expands | 3 |
| UT07 | Inclusion/exclusion/undefined axis | Query Confineable for multiple values | true only when all input values are allowed; an undefined axis permits them | 2 |
| UT08 | Inclusion or undefined axis | ConfineableExcept | Set difference, no change, false when all values are removed, creation of an exclusion condition for an undefined axis | 4 |
| UT09 | Exclusion or undefined axis | ConfineableExcept | Union of exclusion sets, duplicates, inputs containing only existing exclusions, expansion of an undefined axis | 4 |

## Result observation and limitations

Existing checks read the axis list in the TestCases property through reflection and compare inclusion flags and definition sets.
Positive and Negative in method names primarily distinguish inclusion-axis and exclusion-axis inputs; they do not directly mean success and failure.
These 27 tests do not collectively claim coverage of default out values on false, preservation of earlier TestCase values, or invalid-input exceptions.
Independent set-based expectations through the public API and repeated checks are covered separately by the [UniTest TestCase table](../../UniTest/TestCase/01.%20Tables.md).

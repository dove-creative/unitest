## Scope

These are the execution-entry-point, work-scheduling, shutdown-waiting, and execution-mode contracts
verified directly by ProjectTest, ProjectSchedulingTest, ProjectShutdownTest, and ExecutionModeTest.
The table organizes 63 existing NUnit cases into 30 contract groups; row counts and parameterized case counts are separate.
It is distinct from the [Project self-tests](../../UniTest/Project/01.%20Tables.md), which use paths generated by UniTest.

## Cancellation and shutdown waiting

| ID | State | - | Action/input | Expected result |
| --- | --- | --- | --- | --- |
| PU19 | Executor running | - | External cancellation | Do not complete before the Actor is released. On return, status is not Executing, there are no subsequent children or remaining work, and process count is 1. |
| PU20 | Designer running | - | Generator returns normally or faults late after external cancellation | Wait for work to terminate without running the Actor. The normal path is Cancelled; a late fault is Failure, preserving the cause exception and one log entry. |
| PU21 | One Executor waits while another fails | - | Stop with stopOnFailure | Return only after the waiting work also terminates. Process count is 2, no work remains, and reports/process count stay unchanged after yielding once following return. |
| PU22 | Actor running in Runner | - | Time limit exceeded | Log the cancellation request once and wait for the Actor to terminate. After return, confirm process count 1 and no remaining work. |

## Verification boundaries

PU01, PU02, PU07, and PU10 check representative paths in the single-candidate SampleProject.
PU16 and the separate Project self-tests supplement complete branch coverage.
PU05 checks the return value for a missing ID, and PU22 checks time limits and shutdown waiting;
they do not verify every Runner return path, processLimit, or failure JSON output.
Diagnostic precedence when Actor failure follows cancellation is outside the verification scope of PU19 and PU20.

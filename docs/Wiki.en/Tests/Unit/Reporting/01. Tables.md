## Scope

This table covers the report snapshots, paths and ancestor preservation, JSON serialization, and file output verified by the existing JsonReportTest.
It documents existing NUnit coverage rather than planning additional tests.
The design basis is the Result snapshots and JSON section of [Implementation](../../../02.%20Implementations.md).
Strings, depth, branch count, and execution modes are input conditions, distinct from node execution, failure, and restoration states.

## State-action table

| ID | State | Action | Input condition | Result checked by the existing test |
| --- | --- | --- | --- | --- |
| RP01 | New project | Replay a path and serialize its report | Three IDs containing spaces, Korean text, quotes, control characters, and similar characters | Execution succeeds with two entries, root and child. Root Lab/parent IDs are null; the child's original ID/history text and Success status are preserved. |
| RP02 | Before node creation/after parent execution | Create a node or append a child | Ordinary Lab and custom ILab with path separator '/' | Reject with ArgumentException without attaching an invalid child or replaying extra ancestor actions. |
| RP03 | Generator fails after creating one child | Generate full and failure reports after execution | Both execution modes, continuing after failure | Preserve the failed root and successful child; the full JSON has 2 entries and the failure report has 1. |
| RP04 | Tree with branches and siblings | Generate selected-subtree and failure reports | Subsequent failure in a leaf under the selected branch | Preserve ancestors, selected branch, leaf, and parent IDs; exclude unrelated siblings. The failure report includes ancestor states. |
| RP05 | Deep path execution complete | Serialize the full report | Depth 120 with the same Lab ID | Check 121 flat entries, final depth 120/parent ID 119, 121 unique nodeId values, and successful JSON parsing. |
| RP06 | Node with a recorded execution error | Generate and serialize a report | Model description also fails, and a successful child exists | Preserve execution-error type/message/inner details, separate ReportError, null model description, and parent/child histories; JSON remains parseable. |
| RP07 | Node with stored execution diagnostics | Generate a report, then mutate the original state | Change Subject after execution and set a later error | Preserve the model description from execution time. Existing report JSON and its read-only list remain unchanged; a new report reflects Failure. |
| RP08 | Detached restored node from an executed path | Restore repeatedly, reexecute, and append a child | Action path 10 → 12 → 15 | Preserve pre-restoration state, final value, full history, ancestors, and depth; the original tree and previously copied ancestor diagnostics remain independent. |
| RP09 | Branching-tree execution complete | Generate and serialize full reports repeatedly | Branching factor 3, depth 5, both execution modes | Check 364 entries, Success for every non-root node, parent IDs preceding children, unique IDs, and identical JSON after return. |
| RP10 | Report generation complete | Export a JSON file | Korean ID and model description | Valid UTF-8 without BOM; file contents match ToJson and preserve newlines, Korean text, and the parsed model description. |
| RP11 | Report with failed, successful, and ready nodes | Serialize with the built-in writer | Control characters, quotes, backslashes, Unicode, and nested exceptions | JSON values match standard serialization; Korean text and emoji are preserved and U+2028 is escaped. |
| RP12 | Execution complete | Serialize a report | ID containing a lone high surrogate | Escape that code unit and successfully encode with strict UTF-8 without exceptions. |

## Counting criteria

There are 12 meaningful state-action cells and 12 test methods.
Expanding the three strings in RP01 and the two execution modes in RP03 and RP09 gives 16 NUnit execution cases.
The 121 and 364 nodes inside reports describe the data sizes verified within cases, not execution-case counts.

## Cancellation synchronization during replay

The following procedure replaced the earlier Sleep/Delay race in N14.

1. Complete the initial Actor call without waiting, leaving the original in Success.
2. Start child creation in a separate Task; in predecessor-path replay, the second Actor call signals entry and waits for a release gate.
3. Verify the entry signal and that the original task is incomplete, then request cancellation.
4. Always release the gate in finally and await the original task to observe termination and exceptions. This also prevents leaked work when an intermediate assertion fails.
5. Check two predecessor Lab executions, the original Success and empty children, OperationCanceledException, no returned new node, and no execution of the new Lab.

The 10-second limit is a bound for reporting deadlock failure. Cancellation timing is determined by the entry signal, not elapsed time.

## Verification scope

CheckNode directly verifies the node's common public state. Restoration cases also check reports and parent relationships for both the original and restored nodes.
NodeExtensionTest uses the subtree sizes and failure-report relationships of a fixed seven-node tree as expectations.
This documentation does not change existing methods or assertions. The execution record for the 47 cases is linked in the [results](03.%20Results.md).

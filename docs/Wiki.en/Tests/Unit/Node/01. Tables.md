## Scope

These are the creation, execution, append, restoration, and tree-aggregation contracts that NodeTest and NodeExtensionTest verify directly through NUnit.
They are distinct from the [Node self-tests](../../UniTest/Node/01.%20Tables.md), which use UniTest path generation.
This table organizes existing code; it does not add tests or domain behavior.

Root is a root without a Lab, Ready has an unexecuted Lab, Success is a continuable success, and Failure is an execution-failure state.
NullLab, Idle, and Executed_NotContinuable in existing method names correspond to Root, Ready, and Failure in this table, respectively.
Executed_NotContinuable cases prepare a failing Lab; they do not also verify the separate state of successful execution followed by termination.

## Node states and actions

| ID | State | - | Action/input | Expected result |
| --- | --- | --- | --- | --- |
| NU01 | Before creation | - | Create with a null or valid Lab | Root or Ready, respectively, at depth 0, with no parent or children and with a model. |
| NU02 | Ready | - | Execute a successful Lab | Success, continuable, no exception, and Lab execution confirmed. |
| NU03 | Ready | - | Execute a failing Lab | Failure, noncontinuable, ExecutionException, and Lab execution confirmed. |
| NU04 | Root/Success/Failure | - | Call Execute | Reject execution or reexecution with InvalidOperationException. |
| NU05 | Root/Ready/Success/Failure | - | Specify a valid external exception and Cancelled | Become Cancelled and noncontinuable while preserving the supplied exception type. |
| NU06 | Root/Ready/Success/Failure | - | Specify a null external exception | ArgumentNullException. |
| NU07 | Root/Ready/Success/Failure | - | Append a null Lab as a child | InvalidOperationException. |
| NU08 | Ready/Failure | - | Append a valid Lab as a child | InvalidOperationException because the parent cannot continue. |
| NU09 | Root/Success | - | Append a valid Lab, then leave it unexecuted or execute it | Preserve the parent-child link and depth; the new node is Ready or Success. The new Lab runs only after Execute. |
| NU10 | Root/Success | - | Append with an already-cancelled token | OperationCanceledException, no returned new node, and preserved parent state and empty children. The predecessor Lab of Success has only its initial execution. |
| N14 | Success | - | Cancel after entering the predecessor Lab's replay Actor | Initial execution and replay total 2 runs; a cancellation exception aborts creation. Check the original Success and empty children, no returned new node, and no execution of the new Lab. |
| NU11 | Root/Success | - | Vary the creation and execution order of two children | Both siblings succeed and attach to the parent. Also check whether the predecessor Lab executes for each parent type. |
| NU12 | Failure | - | Detach, restore, and reexecute the new node | The restored node is Ready without a parent and leaves the original graph and failure reports unchanged. The original failure remains even if the restored node succeeds. |
| NU13 | Failure with a predecessor path/restored Success | - | Replay the predecessor path or detach and restore again | Preserve original siblings and children, and retain the restored node's depth, history, and diagnostic ancestor links. Repeated restoration produces Ready. |
| NU18 | Any state | - | Inspect the public Afters type | It is a read-only list, and only Node adds children. |

N14 was moved from the self-test documentation while retaining the identifier used in existing code comments and enhancement records.
NU01–NU13, NU18, and N14 form 15 contract groups corresponding to the 39 parameterized cases in NodeTest.

## Tree queries and aggregation

| ID | State | - | Action/input | Expected result |
| --- | --- | --- | --- | --- |
| NU14 | Root/intermediate node/leaf | - | GetCount | Subtree size including the node itself. Results for the seven-node fixture are 7, 2, 1, 3, 1, 1, and 1. |
| NU15 | Tree without Failure or Cancelled | - | AllSucceed | true, with cancellation false. The fixture includes Ready nodes. |
| NU16 | Tree containing cancelled or failed nodes | - | AllSucceed | The cancellation-only case returns true with cancellation true; the failure-only case returns false. |
| NU17 | No failure/single failure/multiple failures | - | GetFailedReports | Return only the root if there is no failure; otherwise return the required ancestors and failed nodes with their original NodeId/ParentId relationships. |

There are four tree-query contract groups and nine NodeExtensionTest execution cases.
The 19 contract groups and 48 NUnit execution cases are distinct counts.

## Verification boundaries

The common per-state checks cover status, depth, parent, children, Lab, ID, model presence, exception type, and continuability.
AllSucceed returning true alone does not establish that every node has completed execution.
Mixed aggregation of a cancelled parent and a failed child is not covered by the separate cancellation and failure cases in NU16.
Per-file method mappings and cancellation synchronization are recorded in the [plan](02.%20Plans.md); historical execution evidence is in the [results](03.%20Results.md).

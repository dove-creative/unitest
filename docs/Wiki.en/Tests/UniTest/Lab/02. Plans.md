## Execution structure

The target file is [LabTest.cs](../../../../../tests/BlackThunder.UniTest.Tests.Recursion/LabTest.cs).
The existing scenario project checks single-step Lab APIs, while a separate small project checks actual repeated execution of the same model.
Both projects explicitly use Inline and ThreadPool.

## Independent reference and cost

Expected scenario IDs are built from a separate fixed list of conditions, without calling the existing CreateLabs or GetExecuteModelCases.
The expected list itself is checked for 133 entries and no duplicates. Assertions check actual root-child IDs, count, depth, model execution counts, and Success throughout,
so an empty tree or missing scenarios cannot be treated as successful.

The repetition project's accumulated value is calculated from the numbers of Add2 and Subtract1 actions in the path. Stage order is compared with a list
that expands the four fixed stage names for each Lab ID on the path. Execution history, model execution count, metadata dictionary, and original templates are also checked.
The outer verification builds paths from node parent relationships, so success is not determined solely by the model's own internal record.

Exhaustive execution is limited to 14 non-root nodes at depth 3. Continuous execution uses depth 8 and executes two candidates at each depth,
giving 16 non-root nodes per seed. Every test runs in both modes, for a total of 12 NUnit tests.
The existing 133 scenarios still stop generating candidates after one execution;
the test that previously described this as repeated execution at depth 100 is replaced with an actual repetition project.

## Verification boundaries

Existing NUnit unit tests and domain code are not changed. Internal NUnit assertions in the incorrect-expectation control run
inside IsolatedContext so the intended internal failure does not contaminate the outer test result.
In safe mode, actual target-code defects are recorded without being fixed. Build and execution are performed as part of the integrated work,
with results distinguished in the [execution record](03.%20Results.md) and [common results](../../Result.md).

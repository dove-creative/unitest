# CompositeLab Self-Test State and Operation Table

## Scope

These tests cover execution order, failure location, expected exceptions, execution limits, and persistent extension. Existing NUnit unit tests remain in place. A separate UniTest project executes all 51 scenarios below.

## States and operations

Ready means a new executable model and composition exist. Execution passes through metadata creation, arrangement, the original action, and assertions in reverse order. An error stops subsequent stages. Successful execution may leave the model continuable, unsustainable, or terminal. Layer position and layer count are inputs rather than states.

| CL51 | Acting | Original expects Exception, extension 1 expects IOE, the original actor throws IOE | Accept a base type as a match and run every assertion | 1 |

IOE is InvalidOperationException and AE is ArgumentException.
Execution succeeds only when the actual exception matches the type on every layer that declares one. An actual exception matching no declaration is preserved, and a partial match fails with MissingExpectedException for the first unmatched layer.

Expected callback traces are derived independently from the forward and reverse ordering contract, never from CompositeLab internals or MetadataGroup.

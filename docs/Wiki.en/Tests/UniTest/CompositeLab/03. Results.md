### Changes made

The minimal fix's bool return was not applied because it treated a match at one layer as satisfying the declarations of every extension.
CompositeLab receives the original Actor's actual exception and compares it directly with every layer's declaration.

- An actual exception that matches no declaration is recorded unchanged as an Act failure.
- If no exception occurs or only some declarations match, execution fails with MissingExpectedException for the first unmatched type; an actual exception, when present, is preserved as InnerException.
- A framework-generated MissingExpectedException is not a candidate for matching, preventing ISSUE-02 from recurring.

Ordinary Lab evaluation and public signatures were not changed.

## Confirmed runtime defect

| Scenario | Input | Expected result | Actual result |
| --- | --- | --- | --- |
| CL30 | The original and extension 1 expect InvalidOperationException, and the original Actor throws it | Accept the expected exception and execute Assert3·2·1·0 | Record MissingExpectedException and skip every Assert |
| CL31 | The original and extension 3 declare the same expected exception | Accept the expected exception and execute Assert3·2·1·0 | Same failure |

The same defect reproduced in both execution modes. It reported that no exception occurred despite the actual target exception being thrown.

The cause was that DoAct in [Lab.cs](../../../../../src/BlackThunder.UniTest/Lab/Lab.cs) (lines 66–87 at verification time) handled the original Lab's expected exception internally without reporting its occurrence to the caller. Lines 69–101 of [CompositeLab.cs](../../../../../src/BlackThunder.UniTest/Lab/CompositeLab.cs) recorded an exception only when DoAct rethrew it, so they missed the exception handled by the original and classified it as a missing expected exception in an extension layer.

## Initial fix proposal and scope at the time

The following is the pre-fix record. This proposal was not applied because of the comparison results in the expected-exception evaluation fix above.

The minimal proposed fix was for internal DoAct to return a bool indicating whether it accepted an actual exception and for CompositeLab to use that result to set expectedExceptionThrown. Ordinary Lab.Execute could ignore the return value to preserve its existing behavior. Existing handling of unexpected and missing exceptions would also remain. No public API change was needed.

The user explicitly limited that work to adding tests and recording the defect, so no runtime fix was applied. The failing CL30·CL31 regression checks and their original expectations were retained. Test authoring, execution, and defect recording for that scope were complete, while the runtime defect remained unresolved. A later fix would reverify both regression scenarios and the full test suite.

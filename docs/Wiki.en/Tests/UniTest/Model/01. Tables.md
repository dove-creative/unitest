## Scope

This table strengthens the remaining-execution-count boundaries and actual execution guarantees of the existing Model self-tests.
It preserves the existing state-specific scenarios and execution depths without changing domain code.

## State-action table

| State | - | Action | Input condition | Expected result | Plan |
| --- | --- | --- | --- | --- | --- |
| Continuable state with an execution-count limit | - | Set a lower remaining count | 1 → 0 | Neither sustainable nor continuable; the expected model has the same state | M01 |
| New self-test project | - | Exhaustive execution with a depth limit | Depth 6, both execution modes | Execute every expected scenario for each state and every required scenario; every node succeeds and execution counts match | M04 |
| New self-test project | - | Continuous execution | Depth 100, seeds 0·1·2, both execution modes | Execute every expected scenario at each step on the selected path; depth and execution counts match | M05 |

The table has 3 meaningful cells. Execution modes and seeds are input conditions for the same contract, not states.
M02·M03 are NUnit-only cases and have been separated into the [Unit Model table](../../Unit/Model/01.%20Tables.md).
M01 is ZeroRemainingCountReplay in Recursion and remains within this self-test scope.

## Execution verification criteria

Expected scenarios are not calculated by reading the generator's actual output.
An explicitly defined list of candidate IDs for each state is used independently of the existing Expected model; the required scenario set for exhaustive execution is also defined separately.
Every non-root result must be Success, and depth, execution count, and execution history must match the path.
Empty trees, missing scenarios, and unexecuted nodes in the Ready state are not accepted as successful.

# UniTest Test Structure and Results

This shared record connects the structure of ordinary unit tests and UniTest-based self-tests with target-specific documentation and overall execution results.
Raw module artifacts are stored in 15 module folders, and each result document links its module's latest TRX and log. The 28 earlier integrated artifacts have been deleted; the earlier results below remain as documentation history.
Ordinary tests verify the target API independently, while self-tests use UniTest's Project and Lab to construct execution paths and verify the framework.
In both projects, NUnit handles test discovery, execution completion, and the final pass/fail verdict.

Issues found by testing and their outcomes are kept in each target's `03. Results.md`.

## Execution

When verifying and reporting a module, filter its fixtures and store the TRX and log beside that module's source documentation.
For a module with multiple fixtures, select all of its fixtures.
Each target's `03. Results.md` provides its latest module execution results and actual command.

The following example runs the three ordinary Lab fixtures.

```powershell
$testRunStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
dotnet test tests/BlackThunder.UniTest.Tests.Unit/BlackThunder.UniTest.Tests.Unit.csproj --configuration Release --no-build --no-restore --filter 'FullyQualifiedName~BlackThunder.UniTest.Tests.Unit.LabTest|FullyQualifiedName~BlackThunder.UniTest.Tests.Unit.LabExtensionTest|FullyQualifiedName~BlackThunder.UniTest.Tests.Unit.ToUncontinuableTest' --results-directory docs/Wiki.ko/Tests/Unit/Lab --logger "trx;LogFileName=$testRunStamp-unit-lab.trx" 2>&1 | Tee-Object -FilePath "docs/Wiki.ko/Tests/Unit/Lab/$testRunStamp-unit-lab.log"
```

Use this example when a Release build of the current source is available.
Use the following commands to verify the full projects together.

```powershell
dotnet build BlackThunder.UniTest.sln --configuration Release --no-restore -m:1
dotnet test BlackThunder.UniTest.sln --configuration Release --no-build --no-restore -m:1 --logger trx
```

Whole-project TRX files from integrated runs are stored directly under `Unit/` for ordinary tests and `UniTest/` for self-tests in the Korean source tree.
Full build and integrated execution logs are stored beside the Korean source document; these shared files provide evidence for the full execution scope.
Module-specific results link directly to their module's TRX and log rather than using only links to full-suite files.
Do not create a separate artifact folder; distinguish artifacts by date and purpose in their filenames.
Generated TRX files and logs are not tracked by Git.

The historical execution figures and commands below are documentation history. Earlier whole-project TRX files and integrated logs have been deleted; current raw evidence is linked from each module's latest result document.
Keep ordinary unit tests alongside self-tests because a self-test runner can miss an error shared with its target.
Detailed boundary cases for worker races, shutdown waiting, and serialization are managed in the corresponding ordinary test documents.

# UniTest 개요

UniTest는 상태별로 가능한 동작을 정의하면 실행 경로를 생성하고 기대 상태를 검증하는 프레임워크이다.

## 목차

1. 목적과 접근
2. 핵심 구조
3. 대표 실행 흐름
4. 독립된 상태의 조합
5. 실행 선택과 결과

## 1. 목적과 접근

상태가 누적되는 객체에서는 같은 동작도 이전 실행 순서에 따라 다른 결과를 만든다. UniTest는 경로를 개별 테스트로 모두 나열하는 부담을 줄이고, 상태-동작 표를 실행 가능한 검증으로 연결한다.

| 항목 | 내용 |
| --- | --- |
| 개요 | 모델의 상태에서 가능한 동작을 생성해 경로를 탐색한다. |
| 목적 | 상태 전환과 연속 동작에 대한 검증 범위를 체계적으로 넓힌다. |
| 구현 | Model, Lab, Node와 Project로 상태·동작·이력·실행 제어를 나눈다. |

테스트 설계자는 유효한 상태와 동작, 기대 결과를 정의한다. 프레임워크는 그 정의와 깊이·실패 중단 같은 실행 조건이 허용하는 경로를 탐색한다. 상태 모델에 없는 동작이나 무한한 경로까지 자동으로 검증하는 것은 아니다.

## 2. 핵심 구조

<img src="../Resources/02-image1.png" alt="UniTest model, lab, node, and project structure" width="655">

- `Model`: 실제 테스트 대상과 기대 상태, 실행 이력을 함께 가진다.
- `Lab`: 한 동작을 Arrange·Act·Assert로 정의한다. `CompactLab`은 간단한 정의를 Lab으로 변환한다.
- `Node`: 특정 경로의 모델, 동작과 결과를 가진다. 부모와 자식 관계가 실행 경로를 만든다.
- `Project`: 현재 모델에서 가능한 Lab을 생성하고 노드의 설계·실행을 조정한다.

실제 상태와 기대 상태를 분리하면 잘못된 동작을 그대로 정답으로 삼는 일을 피할 수 있다. 상태-동작 표의 작성 기준은 [테스트 방법론](00-Unit-Test-Guideline.md)을 따른다.

## 3. 대표 실행 흐름

1. 프로젝트가 초기 모델을 가진 루트 노드를 만든다.
2. 현재 모델에서 실행할 수 있는 Lab을 생성한다.
3. 각 동작에 대해 이전 경로를 재현한 모델을 준비한다.
4. 기대 상태를 준비하고 실제 동작을 수행한 뒤 결과를 비교한다.
5. 계속 실행할 수 있는 노드에서 다음 동작을 생성한다.
6. 깊이 제한, 실패 중단 또는 취소 조건에 따라 종료하고 결과를 반환한다.

이 흐름에서 테스트 대상의 생명주기와 부작용은 모델 및 시나리오가 책임진다. 프레임워크는 임의의 외부 시스템을 자동으로 복제하거나 되돌리지 않는다.

## 4. 독립된 상태의 조합

탑승 상태, 배터리 상태와 충전 상태처럼 여러 상태 축을 가진 객체는 하나의 거대한 표 대신 축별 규칙으로 구성할 수 있다.

- `TestCase`: 현재 조합에서 허용하는 동작과 조건을 표현한다.
- `Merge`: 상태별 규칙과 실제 동작 템플릿을 하나의 Lab으로 합친다.
- `Extend`: 여러 Lab의 준비·검증 계층을 결합하되 실제 동작은 원본에서 수행한다.

각 축은 자신이 책임지는 상태를 준비하고 검증한다. 조합 순서와 구체적인 작성 예제는 [사용법](04-Usage.md)의 다중 상태 튜토리얼에 있다.

## 5. 실행 선택과 결과

전체 경로 탐색은 상태 조합을 넓게 검사하고, 연속 실행은 지속 가능한 한 경로를 선택하며 긴 이력을 검사한다. 저장한 Lab ID 경로를 재실행하면 특정 실패에 집중할 수 있다.

실행 결과는 노드 트리로 반환한다. JSON 리포트는 그 결과를 독립된 값으로 저장하며, 실패 리포트에는 실패 노드와 경로를 설명하는 조상이 포함된다. 실행 모드, 취소와 실패 처리의 내부 책임은 [구현](02-Implementations.md), 호출 방법은 [사용법](04-Usage.md)을 참고한다.

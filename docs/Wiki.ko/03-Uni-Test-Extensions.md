# UniTest 실행 확장

실패 후 중단, 경로 재현, 연속 테스트 실행을 설명하는 문서이다. 실행 가능한 API 예제는 [사용법](04-Usage.md)의 6절을 참고한다.

## 실패 후 중단

`Project.Execute`는 실패 후 새 작업 예약을 중단할 수 있다. 이미 시작한 작업자는 완료까지 기다리고 오류를 관찰한 뒤 결과 트리를 반환한다. 중단은 동기 콜백을 강제로 끊지 않는다.

실행이 끝난 뒤 `GetFailedReports()`를 사용하면 실패 노드와 그 조상 경로를 보존한다. 취소 노드는 별도 상태이며 일반적인 검증 실패로 바뀌지 않는다.

## 경로 재현

노드의 실행 이력을 읽고 `/`로 구분한 Lab ID를 `Execute(ids)`에 전달한다. UniTest는 새 모델을 만들고 같은 경로를 따른다. Lab ID와 구분자는 0.4.0 네임스페이스 변경 후에도 유지한다.

현재 상태에 없는 ID는 `ArgumentException`을 발생시킨다. Lab 내부 실패는 해당 Node에 기록한다. `Run(..., executionIds)` 도우미는 실행 오류를 전파하는 대신 로그를 남기고 `false`를 반환한다.

## 노드 디버깅

1. 실행을 마친 결과 트리에서 노드를 선택한다.
2. `node.DetachAndRestore()`로 별도 노드를 만들고 앞선 실행 이력을 복원한다.
3. 중단점을 설정하고 `restored.Execute()`로 선택한 Lab을 재실행한다.

분리된 노드는 원본 결과 그래프를 변경하지 않는다. 재현 가능성은 실제 객체와 테스트 입력의 재현 가능성에도 의존한다.

## 지속 가능한 경로의 연속 실행

전체 탐색의 경로 수는 깊이에 따라 지수적으로 늘 수 있다. 분기 수가 `b`, 깊이가 `d`로 고정되면 경로 수는 대략 `b^d` 규모가 될 수 있다. 일반적으로 이차 복잡도라고 설명할 수 없다.

`ExecuteContinuously`는 각 단계의 후보를 검사하고 지속 가능한 경로 하나를 이어 간다. 실행 이력과 seed로 경로를 결정적으로 선택한다. 후보 수가 `b`로 고정되면 후보 실행 수는 대략 `b × d`에 비례하지만, 실제 수행 시간에는 객체 생성·이력 재현·콜백의 비용도 영향을 준다.

연속 실행은 긴 상태 이력을 검사하는 데 유용하다. 모든 조합을 다루지는 않으므로 제한된 깊이의 전체 탐색과 특정 경로 재현을 함께 사용한다.

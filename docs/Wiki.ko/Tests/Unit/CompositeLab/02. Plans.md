# CompositeLab NUnit 단위 테스트 계획

## 목차

- 대상과 fixture
- 계약과 메서드 대응
- 검증의 경계

## 대상과 fixture

대상은 [CompositeLabTest](../../../../../tests/BlackThunder.UniTest.Tests.Unit/CompositeLabTest.cs)이다. SetUp에서 세 Lab, 처음 두 Lab의 CompositeLab과 새 Model을 준비한다.
SetLabs가 선택한 두 Lab의 단계별 실패를 주입하고, TearDown이 참조를 정리한다.
현재 구현된 메서드와 입력 생성기를 문서화한 계획이며, 추가 검증은 [공통 결과](../../Result.md)의 별도 기록을 따른다.

## 계약과 메서드 대응

| 표 ID | 실제 메서드와 입력 | 검증 방식 | 사례 수 |
| --- | --- | --- | --- |
| UC01 | Execute_NullModel | ExecutionException과 Model setting failed 메시지 | 1 |
| UC02 | Execute_Model / GetTestCases | 계층별 내부 ProbeException 메시지, Continuable, 확장 Actor 미실행에 따른 성공 | 7 |
| UC03 | Execute_ExtensionExpectedException | 확장에 설정한 ProbeException이 발생하지 않은 경우 MissingExpectedException의 형식 확인 | 1 |
| UC04 | CheckMetadata / GetProperties | ToUnsustainable·ToUncontinuable 결합과 남은 횟수 최소값·무제한 상태 비교 | 144 |
| UC05 | Extend / GetTestCases_Ordered | (lab1,lab2), (lab2,lab3), (lab1,lab3)에 일곱 실패·성공 조건 적용 | 21 |

## 검증의 경계

UC05는 확장 후 동작과 오류의 결과를 확인하는 검사이다. 기존 조합의 영속적 보존이나 모든 호출 순서를 별도로 단언한다고 확대하여 해석하지 않는다.
여러 계층에 예상 예외를 선언한 조합의 검증은 [UniTest CompositeLab](../../UniTest/CompositeLab/02.%20Plans.md)의 범위이다.
단위 테스트 통과 수에 해당 자체 테스트 결과를 합산하지 않는다. 기존 결과는 [실행 기록](03.%20Results.md)에 둔다.

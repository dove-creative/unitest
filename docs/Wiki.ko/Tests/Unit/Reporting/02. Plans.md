# Reporting 단위 테스트 대응 계획

## 목차

- 기존 테스트 구성
- 표와 메서드 대응
- 검증 기준과 한계

## 기존 테스트 구성

대상 코드는 [JsonReportTest.cs](../../../../../tests/BlackThunder.UniTest.Tests.Unit/JsonReportTest.cs)이다.
기존 코드를 상태표에 대응시킨 계획 문서이며, 표의 항목은 이미 구현된 검증 범위이다.
실제 Node·Project로 결과를 만들고 NUnit으로 스냅샷의 값과 JSON을 직접 검증하는 구조이다.
문자열과 수치 기대값, 표준 JSON 파서·직렬화기 및 실제 출력 파일이 비교 기준이다.

## 표와 메서드 대응

| 표 | 기존 메서드 | 매개변수와 실행 사례 수 |
| --- | --- | --- |
| RP01 | SpecialIdsCanExecuteReplayAndRoundTrip | 문자열 3개, 3사례 |
| RP02 | SlashIsRejectedBeforeAttachingOrReplaying | 1사례 |
| RP03 | IteratorFailureRetainsCompletedChildren | ThreadPool·Inline, 2사례 |
| RP04 | SelectedSubtreeIncludesAncestorsWithoutSiblings | 1사례 |
| RP05 | DeepPathsSerializeWithoutNestedJsonDepthGrowth | 1사례 |
| RP06 | ModelDescriptionFailureDoesNotLoseExecutionFailureOrChildren | 1사례 |
| RP07 | ReportsAndExecutionDiagnosticsAreIndependentSnapshots | 1사례 |
| RP08 | RepeatedRestoreAndAppendReplayAncestorsAndPreserveOriginal | 1사례 |
| RP09 | BranchingReportsAreCompleteAndStableAfterExecution | ThreadPool·Inline, 2사례 |
| RP10 | ExportWritesIndentedUtf8JsonWithoutBom | 1사례 |
| RP11 | BuiltInWriterMatchesSerializerOutput | 1사례 |
| RP12 | LoneSurrogatesAreEscapedSoReportsStayValidUtf8 | 1사례 |
| 합계 | 12개 메서드 | 16사례 |

RP03은 생성기가 첫 Lab을 반환한 뒤 실패하는 조건이며 실패 시 중단을 끈 실행이다.
RP08은 원본 트리의 JSON과 복원한 노드의 조상 스냅샷을 각각 저장한 뒤 원본 변경과 비교하는 구조이다.
RP10은 임시 폴더에 파일을 저장해 바이트와 파싱 결과를 확인하고 종료 시 폴더를 정리한다.
RP11은 CamelCase 표준 직렬화 결과와 내장 작성기의 결과를 JsonNode 값으로 비교하는 검증이다.

## 검증 기준과 한계

RP01·RP05·RP09는 예상 노드 수를 명시하고, RP05·RP09는 nodeId 유일성도 확인한다.
RP07·RP08의 전후 JSON 비교는 동일 객체에서 이전에 얻은 스냅샷이 바뀌지 않는 계약의 검증이다.
RP11의 JSON 비교는 문자 이스케이프의 모든 표현이 동일해야 한다는 요구가 아니라 파싱한 값의 동등성 검증이다.
RP12는 단독 상위 surrogate의 이스케이프와 UTF-8 인코딩을 확인한 범위이며 모든 잘못된 유니코드 조합을 전수 조사한 테스트는 아니다.
이 파일의 두 모드 매개변수 검증은 RP03·RP09에 한정된다.

# Reporting 단위 테스트 상태-동작 표

## 목차

- 범위
- 상태-동작 표
- 집계 기준

## 범위

기존 JsonReportTest가 검증하는 보고서 스냅샷, 경로와 조상 보존, JSON 직렬화 및 파일 출력의 상태표이다.
새 테스트를 추가하는 계획이 아니라 기존 NUnit 검증 범위를 정리한 문서이다.
설계 기준은 [구현](../../../02.%20Implementations.md)의 결과 스냅샷과 JSON 절이다.
문자열, 깊이, 분기 수와 실행 모드는 입력 조건이며 노드의 실행·실패·복원 상태와 구분한다.

## 상태-동작 표

| --- | --- | --- | --- | --- |
| RP01 | 새 프로젝트 | 경로 재현 후 보고서 직렬화 | 공백·한글·따옴표·제어 문자 등이 있는 ID 세 가지 | 실행 성공, 루트와 자식 두 항목, 루트의 Lab·부모 ID는 null, 자식의 ID·이력 원문과 Success 상태를 보존한다. |
| RP02 | 노드 생성 전·부모 실행 완료 | 노드 생성 또는 자식 추가 | 경로 구분자 '/'가 있는 일반 Lab 및 사용자 ILab | ArgumentException으로 거부하며 잘못된 자식을 연결하거나 조상 동작을 추가 재현하지 않는다. |
| RP03 | 자식 하나를 생성한 뒤 생성기 실패 | 실행 완료 후 전체·실패 보고서 생성 | 두 실행 모드, 실패 시 계속 실행 | 실패한 루트와 성공한 자식을 보존하며 전체 JSON 항목 수는 2, 실패 보고서 항목 수는 1이다. |
| RP04 | 분기와 형제가 있는 트리 | 선택한 부분 트리 및 실패 보고서 생성 | 선택 분기 아래 리프의 후속 실패 | 조상·선택 분기·리프와 부모 ID를 보존하고 무관한 형제는 제외한다. 실패 보고서는 조상 상태를 포함한다. |
| RP05 | 깊은 경로 실행 완료 | 전체 보고서 직렬화 | 같은 Lab ID로 깊이 120 | 평탄한 121개 항목, 마지막 깊이 120·부모 ID 119, 고유한 nodeId 121개와 JSON 파싱 성공을 확인한다. |
| RP06 | 실행 오류가 기록된 노드 | 보고서 생성·직렬화 | 모델 설명 함수도 실패하고 성공한 자식이 존재 | 실행 오류의 형식·메시지·내부 상세, 별도 ReportError, 모델 설명 null, 부모·자식 이력을 보존하며 JSON 파싱이 가능하다. |
| RP07 | 실행 진단을 저장한 노드 | 보고서 생성 후 원본 상태 변경 | 실행 후 Subject 변경과 후속 오류 설정 | 실행 당시 모델 설명을 보존하며 기존 보고서 JSON과 읽기 전용 목록은 유지되고 새 보고서에는 Failure가 반영된다. |
| RP08 | 실행한 경로의 분리된 복원 노드 | 반복 복원·재실행 후 자식 추가 | 10 → 12 → 15의 동작 경로 | 복원 전 상태·최종 값·전체 이력·조상과 깊이를 보존하며 원본 트리와 이미 복사한 조상 진단은 독립적이다. |

| RP10 | 보고서 생성 완료 | JSON 파일 내보내기 | 한글 ID와 모델 설명 | BOM 없는 유효한 UTF-8이며 ToJson과 파일 내용이 같고 개행·한글·파싱한 모델 설명을 보존한다. |
| RP11 | 오류·성공·대기 노드를 가진 보고서 | 내장 작성기로 직렬화 | 제어 문자·따옴표·역슬래시·유니코드·중첩 예외 | 표준 직렬화 결과와 JSON 값이 같으며 한글·이모지는 유지하고 U+2028은 이스케이프한다. |
| RP12 | 실행 완료 | 보고서 직렬화 | 단독 상위 surrogate가 포함된 ID | 해당 코드 단위를 이스케이프하고 엄격한 UTF-8 인코딩이 예외 없이 성공한다. |

## 집계 기준

유의미한 상태-동작 칸과 테스트 메서드는 각각 12개이다.
RP01의 문자열 세 가지와 RP03·RP09의 두 실행 모드를 전개하면 NUnit 실행 사례는 16개이다.
보고서 내부의 121개·364개 노드는 실행 사례 수가 아니라 해당 사례에서 확인하는 데이터 크기이다.

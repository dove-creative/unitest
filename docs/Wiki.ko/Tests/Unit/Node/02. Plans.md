## 재현 중 취소 동기화

N14의 기존 Sleep·Delay 경쟁을 제거한 절차는 다음과 같다.

1. 최초 Actor 호출은 대기 없이 끝내어 원본을 Success로 만든다.
2. 별도 Task에서 자식 생성을 시작하고, 두 번째 Actor 호출인 선행 경로 재현에서 진입 신호를 보낸 뒤 해제 gate를 기다린다.
3. 테스트는 진입 신호와 원작업 미완료를 확인한 뒤 취소한다.
4. finally에서 항상 gate를 해제하고 원작업을 await하여 종료와 예외를 관찰한다. 중간 검증 실패도 작업을 남기지 않는 경로이다.
5. 선행 Lab 실행 2회, 원본 Success와 빈 자식, OperationCanceledException, 새 노드 미반환과 새 Lab 미실행을 확인한다.

10초 제한은 교착 시 실패를 보고하기 위한 상한이다. 취소 시점을 결정하는 기준은 경과 시간이 아니라 진입 신호이다.

## 검증 범위

CheckNode는 노드의 공통 공개 상태를 직접 확인하고, 복원 사례는 원본과 복원본의 보고서·부모 관계를 함께 확인한다.
NodeExtensionTest는 고정된 7개 노드 트리의 서브트리 크기와 실패 보고서 관계를 기대값으로 사용한다.
이 문서화에서 기존 메서드나 단언을 변경하지 않으며, 47개 사례의 실행 기록은 [결과](03.%20Results.md)에 연결한다.

## 예상 예외 판정 수정

### 추가로 확인한 결함

CL30·CL31의 결함을 재검토하면서 기존 최소 수정안을 저장소 밖 임시 복사본에 적용해 현재 코드와 비교했다.
아래 표의 IOE는 InvalidOperationException, AE는 ArgumentException이며, Missing은 해당 형식의 MissingExpectedException 실패를 뜻한다.

| 시나리오 | 계층별 선언 | 실제 예외 | 수정 전 | 최소 수정안 | 수정 후 |
| --- | --- | --- | --- | --- | --- |
| CL30·CL31 | 원본 IOE, 확장 IOE | IOE | Missing IOE | 통과 | 통과 |
| CL46 | 원본 IOE, 확장 1 AE | IOE | Missing AE | 통과(회귀) | Missing AE, 실제 예외 보존 |
| CL47 | 원본 Exception | 없음 | 통과(결함) | 통과(결함) | Missing Exception |

최소 수정안 열은 임시 복사본에서 2~3계층으로 실행한 결과이다. 그 임시 실행의 산출물은 보관하지 않았다.
CL47·CL48은 원본 Lab이 던진 MissingExpectedException을 Exception 선언이 받아들여 예외 없이 통과한 결함이다.
CL49·CL50의 수정 전 통과는 한 계층만 일치해도 성공으로 보던 동작이다. 선언한 모든 계층이 일치해야 한다는 계약으로 정하고 실패로 바꾸었다.

### 수정 내용

최소 수정안의 bool 반환은 한 계층의 일치를 모든 확장의 선언이 충족된 것으로 처리하므로 적용하지 않았다.
CompositeLab은 원본 Actor의 실제 예외를 받아 모든 계층의 선언과 직접 대조한다.

- 어느 선언과도 맞지 않는 실제 예외는 그대로 Act 실패로 기록한다.
- 예외가 없거나 일부 선언만 일치하면 일치하지 않은 첫 형식의 MissingExpectedException으로 실패하며, 실제 예외가 있으면 InnerException으로 보존한다.
- 프레임워크가 만든 MissingExpectedException은 대조 대상이 아니므로 CL47·CL48의 결함이 재현되지 않는다.

일반 Lab의 판정과 공개 시그니처는 변경하지 않았다.

## 확인된 런타임 결함

| 시나리오 | 입력 | 기대 결과 | 실제 결과 |
| --- | --- | --- | --- |
| CL30 | 원본과 확장 1이 InvalidOperationException을 예상하며 원본 Actor가 해당 예외 발생 | 예상 예외 수용 후 Assert3·2·1·0 실행 | MissingExpectedException을 기록하고 모든 Assert 생략 |
| CL31 | 원본과 확장 3이 같은 예상 예외를 선언 | 예상 예외 수용 후 Assert3·2·1·0 실행 | 같은 실패 |

두 실행 모드에서 같은 결함이 재현되었다. 실제 대상 예외가 발생했음에도 예외가 발생하지 않았다고 판단한다.

원인은 [Lab.cs](../../../../../src/BlackThunder.UniTest/Lab/Lab.cs)의 DoAct(검증 시점 66–87행)가 원본의 예상 예외를 내부에서 처리하고 호출자에게 발생 여부를 전달하지 않는 데 있다. [CompositeLab.cs](../../../../../src/BlackThunder.UniTest/Lab/CompositeLab.cs)의 69–101행은 DoAct가 예외를 다시 던진 경우에만 발생 여부를 기록하므로, 원본에서 처리한 예외를 놓치고 확장 계층의 예상 예외 미발생으로 분류한다.

## 최초 수정 제안과 당시 범위

아래는 수정 전 기록이다. 이 제안은 위 예상 예외 판정 수정의 비교 결과에 따라 적용하지 않았다.

최소 수정안은 내부 DoAct가 수용한 실제 예외의 발생 여부를 bool로 반환하고 CompositeLab이 그 결과로 expectedExceptionThrown을 설정하는 것이다. 일반 Lab.Execute는 반환값을 무시하여 기존 동작을 유지할 수 있다. 예상과 다른 예외 및 미발생 예외의 기존 처리도 유지한다. 공개 API 변경은 필요하지 않다.

사용자가 이번 작업 범위를 테스트 추가와 결함 기록으로 명시하여 런타임 수정은 적용하지 않았다. CL30·CL31의 실패하는 회귀 검증과 원래 기대값을 유지한다. 이번 범위의 테스트 작성·실행·결함 기록은 완료하였으며, 런타임 결함은 미해결 상태이다. 추후 수정 작업에서는 두 회귀 시나리오와 전체 테스트를 재검증한다.

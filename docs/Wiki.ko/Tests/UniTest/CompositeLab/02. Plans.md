# CompositeLab 자체 테스트 계획

## 실행 구조

테스트 코드는 `tests/BlackThunder.UniTest.Tests.Recursion/UniTest/CompositeLabTest.cs`에 둔다. ScenarioProject가 51개의 Lab을 생성하고, 각 Lab이 별도 대상 모델과 조합을 실행한다. 전체 실행은 두 실행 모드에서 수행하며 완료한 시나리오 ID, 자식 수, ProcessCount를 확인해 빈 실행의 성공을 방지한다.

## 표와 코드 대응

| 표 | 코드 | 검증 |
| --- | --- | --- |
| CL01–CL44, CL46–CL51 | CreateScenarios, ExecuteScenario, ExpectedTrace | 계층별 콜백 순서, 오류와 내부 예외, 최종 제한, 메타데이터와 템플릿 보존 |
| CL45 | VerifyPersistentExtensions, VerifyComposition | 반복·분기 확장 후 각 조합 재실행, 원본 보존 |
| 전체 | AllScenariosExecute | 51개 시나리오 전수 실행, 취소 없음, 모든 결과 성공 |
| CL03·CL16·CL41·CL45 | SelectedScenarioReplays | ID 기반 독립 재현과 실행 완료 확인 |

## 독립성 및 실패 대응

예상 이력은 실행 계약에 따른 문자열 배열이고, 제한 결과는 시나리오의 명시적 상수이다. 대상 오류는 관찰값으로 수집하여 외부 Lab에서 검증한다. 예상한 대상 오류와 자체 테스트의 검증 실패를 구분한다.

CL46–CL51은 계층별 예상 형식을 ExpectedByLayer로 지정하고, 미충족 형식과 실제 예외 보존을 ExpectedMissingType·ActorFailure로 확인한다. 기존 ID가 바뀌지 않도록 CL45 뒤에 추가한다.

기본 안전 모드를 따른다. 테스트 작성 오류는 수정하며, 실제 런타임 결함은 실패 시나리오와 함께 기록하고 보고한다. 설계자의 승인 없이 런타임 코드를 변경하거나 결함에 맞춰 기대값을 낮추지 않는다.

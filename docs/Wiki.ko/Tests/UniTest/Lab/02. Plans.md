## 실행 구조

대상 파일은 [LabTest.cs](../../../../../tests/BlackThunder.UniTest.Tests.Recursion/LabTest.cs)이다.
기존 시나리오 프로젝트는 단일 단계의 Lab API 검사를 담당하고, 별도 작은 프로젝트는 같은 모델의 실제 반복 실행을 담당한다.
두 프로젝트 모두 Inline과 ThreadPool을 명시적으로 사용한다.

## 독립 기준과 비용

시나리오의 기대 ID는 기존 CreateLabs나 GetExecuteModelCases를 호출하지 않고 별도의 고정 조건 목록으로 구성한다.
기대 목록 자체도 133개이며 중복이 없는지 확인한다. 실제 루트 자식의 ID·개수·깊이·모델 실행 수와 전체 Success를
검사하므로 빈 트리나 일부 시나리오 누락을 성공으로 간주하지 않는다.

반복 프로젝트의 누적값은 경로에 나타난 Add2와 Subtract1의 횟수로 계산한다. 단계 순서는 각 경로의 Lab ID에 대해
고정된 네 단계 이름을 펼친 목록으로 비교한다. 실행 이력·모델 실행 수·메타데이터 사전·원본 템플릿도 함께 확인한다.
외부 검증은 노드의 부모 관계로 경로를 구성하므로 모델 내부의 자체 기록만으로 성공을 판정하지 않는다.

전수 실행은 깊이 3의 비루트 노드 14개로 제한한다. 연속 실행은 깊이마다 두 후보를 실행하는 깊이 8이며,
각 seed의 비루트 노드는 16개이다. 모든 테스트를 두 모드에서 수행하므로 NUnit 테스트는 총 12개이다.
기존 133개 시나리오에서 한 번 실행하면 후보 생성을 중단하는 구조는 유지하며,
이를 깊이 100의 반복 실행으로 표시하던 테스트는 실제 반복 프로젝트로 교체한다.

## 검증 경계

기존 NUnit 단위 테스트와 도메인 코드는 변경하지 않는다. 잘못된 기대값 대조군의 내부 NUnit 검증은
IsolatedContext에서 실행하여 의도한 내부 실패가 외부 테스트 결과를 오염시키지 않도록 한다.
안전 모드에서 실제 대상 코드 결함은 기록하며 수정하지 않는다. 빌드와 실행은 통합 작업에서 수행하고,
결과는 [실행 기록](03.%20Results.md) 및 [공통 결과](../../Result.md)에서 구분한다.

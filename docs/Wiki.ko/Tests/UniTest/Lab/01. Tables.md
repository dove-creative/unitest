# Lab 자체 테스트 상태-동작 표

## 목차

- 범위
- 기존 시나리오
- 반복 실행
- 실행 보장

## 범위

기존 Lab 자체 테스트의 133개 시나리오를 유지하면서 실제 실행 여부와 반복 실행의 상태 보존을 검증하는 보강이다.
실행 모드는 Inline과 ThreadPool이며, 대상 코드는 변경하지 않는다.

## 기존 시나리오

조건 조합은 첫 실패 이후의 불필요한 조합을 제외한 31개이다. 각 조합을 생성자 메타데이터 유무에 따라 실행하므로
실행 검사와 복사 검사가 각각 62개이다. 기존 시나리오가 검사하는 계약을 다음 다섯 칸으로 묶는다.

| ID | 입력·동작 | 기대 결과 |
| --- | --- | --- |
| LB-M01 | null 모델 실행 | 모델 설정 실패가 ExecutionException으로 보고됨 |
| LB-M02 | 메타데이터·준비·실행·검증 단계의 성공·실패 조합 62개 | 기존 예외·계속 실행 가능 여부·남은 실행 수 기대값 유지 |
| LB-M03 | 생성자 또는 대리자를 통한 메타데이터 전달 2개 | 지정한 메타데이터 값 전달 |
| LB-M04 | 남은 실행 수 병합 6개 | 무제한 처리 및 더 작은 제한 선택 |
| LB-M05 | Lab 복사 조합 62개 | ID 교체, 대리자와 메타데이터 설정 보존 |

## 반복 실행

상태는 직전 실행의 유무로 구분한다. 누적 정수와 실행 횟수는 검증 자료이다.
Add2와 Subtract1은 각각 정수에 2를 더하거나 1을 빼는 작은 Lab이며 같은 인스턴스를 반복 사용한다.

| 상태 | - | Add2 | Subtract1 |
| --- | --- | --- | --- |
| | - | 정수에 2 추가 | 정수에서 1 차감 |
| | - | | |
| 최초 실행 | - | LB-R01: **반복 가능**, `[메타데이터 생성·단계 순서·이력 1개]` | LB-R02: **반복 가능**, `[메타데이터 생성·단계 순서·이력 1개]` |
| 반복 가능 | - | LB-R03: `[직전 메타데이터 제거·새 메타데이터·누적값·순서 있는 이력]` | LB-R04: `[직전 메타데이터 제거·새 메타데이터·누적값·순서 있는 이력]` |

각 실행은 SetMetadata → Arrange → Act → Assert 순서이다. 홀수 번째 실행은 준비 단계에서 예상 예외를 지정하고
실행 단계에서 해당 예외를 발생시키며, 짝수 번째 실행에는 예상 예외가 없어야 한다.
이를 통해 이전 실행의 메타데이터가 다음 실행이나 원본 템플릿으로 유출되지 않는지도 확인한다.

## 실행 보장

| ID | 입력·동작 | 기대 결과 |
| --- | --- | --- |
| LB-G01 | 기존 시나리오 프로젝트 깊이 1 실행 | 독립 목록의 ID 133개가 정확히 한 번씩 존재하고 모두 Success, 각 모델 실행 수 1 |
| LB-G02 | 작은 반복 프로젝트의 전수·연속 실행 | 깊이 3 전수 14개 또는 깊이 8 연속 16개 실행, 모든 노드 Success, 각 경로의 값·이력·단계 수 일치 |
| LB-G03 | 반복 프로젝트에 잘못된 누적값 기대 주입 | 실행된 노드가 Failure이고 실제 검증 예외가 보존됨 |

전체 범위는 기존 시나리오 5칸, 반복 상태-동작 4칸, 실행 보장 3칸을 합한 12칸이다.
133개 시나리오를 여러 깊이로 분기시키지 않으며, 반복 검증은 두 동작만 사용한다.

# TestCase 자체 테스트 계획

## 구현과 대응

대상 파일은 [TestCaseTest.cs](../../../../../tests/BlackThunder.UniTest.Tests.Recursion/UniTest/TestCaseTest.cs)이다. 테스트 실행 전 [상태-동작 표](01.%20Tables.md)를 기준으로 계획한 36칸을 모두 구현한다.

| 테스트 | 표 대응 | 검증 방식 |
| --- | --- | --- |
| BoundedExplorationCoversEveryStateOperation | TC-상태-동작 24칸 | 네 초기 상태에서 깊이 3까지 탐색하며 두 번의 동작 조합을 실행한다. Inline과 ThreadPool을 각각 검사한다. |
| ContinuousSequencesPreserveEarlierValues | TC-상태-동작 | 시드 0, 7, 23으로 깊이 16의 연속 경로와 모든 단계 후보를 검사한다. |
| MixedPathsKeepIndependentExpectations | TC-상태-동작 | 포함·제외 전환, 실패한 Try, 빈 포함 집합, 축 추가를 섞은 세 경로를 재현한다. |
| InvalidInputsPreserveTheOriginal | TC-B01부터 TC-B11 | 경계 입력을 11개 독립 Lab으로 실행하고 예외와 원본 보존을 검증한다. |
| WrongOracleIsReportedAsFailure | TC-F01 | 틀린 기대 집합을 주입하여 검사기와 자체 실행기가 실패를 탐지하는지 확인한다. |

## 독립 기대 모델

기대 모델은 각 축의 포함·제외 모드와 다섯 값의 허용 비트 집합을 보관한다. 기대값은 입력으로부터 비트 합집합·차집합으로 계산하며, TestCase의 비공개 필드나 실제 반환값으로 기대값을 만들지 않는다. Count, 인덱서와 Confineable 공개 API로 현재 값과 모든 이전 스냅샷을 검사한다.

각 변경은 이전 TestCase와 기대 집합 복사본을 저장한다. Try 동작은 예상 성공 여부와 out 결과를 비교한 뒤 성공했을 때만 현재 값을 교체한다. 검사기의 잘못된 기대값 대조는 격리된 NUnit 실행 문맥에서 실행하고, 원래 문맥으로 복귀한 뒤 실패 결과를 직접 확인한다.

## 실행과 누락 방지

유한 탐색은 네 초기 Lab과 각 상태의 11개 동작을 사용한다. 깊이 3에서 루트를 포함한 533개 노드와 24개 상태-동작 식별자가 모두 관찰되어야 한다. 모든 비루트 노드가 Success인지 직접 확인하여 실행되지 않은 Ready 노드가 성공처럼 처리되는 것을 막는다.

연속 실행은 최대 깊이 16과 최소 실행 노드 수를 확인한다. 명시 경로는 길이, 마지막 축 값과 축 개수도 검사한다. 경계 검사는 11개 Lab 식별자가 모두 결과에 포함되어야 한다. 공유 런타임 코드와 기존 단위 테스트는 수정하지 않는다.

# Project 자체 테스트 계획

## 구성

코드는 [ProjectTest.cs](../../../../../tests/BlackThunder.UniTest.Tests.Recursion/UniTest/ProjectTest.cs)에 둔다. 기존 Recursion 프로젝트의 소스 참조와 NUnit 실행기를 사용한다.

외부 `ScenarioProject`는 각 검증을 `Lab<Model>`로 생성한다. Lab은 작은 내부 `CounterProject`를 실행하고 결과를 검증한다. 동기 Lab 안에서 비동기 실행을 기다리는 구간은 외부 ThreadPool 작업자에서 수행한다. 시간 대기나 타이밍 추측으로 실행 순서를 만들지 않는다.

## 표와 코드 대응

| 표 | 함수 | 검증 방식 |
| --- | --- | --- |
| P01 | `VerifyDepth` | 별도 경로 열거기로 만든 경로 집합, 계산 값, 분기별 모델 인스턴스, ProcessCount 비교 |
| P02 | `VerifyReplay` | 지정 경로의 접두 집합 및 전체 탐색 결과와 비교 |
| P03 | `VerifyContinuous` | 후보 수·확장 분기 검증, 같은 seed 반복·모드 간 비교, 최장 경로 재현 |
| P04 | `VerifyNoContinuation` | 빈 생성기와 종료 전용 생성기의 깊이·연속 실행 결과 확인 |
| P05 | `VerifyFailure` | 세 진입점의 명시적 실패·원인 예외·확장 중단 확인 |
| P06 | `VerifyContinueAfterFailure` | 실패 형제와 성공 후속 노드의 공존, 실패 리포트 범위 확인 |
| P07 | `VerifyGeneratorFailure`, `VerifyUnknownPath` | 부분 생성 보존과 잘못된 경로 예외 확인 |
| P08 | `VerifyExternalCancellation` | 세 진입점에서 사용자 코드 호출 0회와 재사용 금지 확인 |
| P09 | `VerifySingleUse` | 첫 실행 이후 모든 진입점 거부 및 취소 후 스냅샷 보존 확인 |
| P10 | `VerifyCancelledProject` | Cancel 반복과 모든 실행 진입점 거부 확인 |

## 실행 및 완전성

`ProjectScenarios`는 `ThreadPool`·`Inline` 각각의 26개 시나리오를 깊이 1로 실행한다. 최종 검증에서 생성된 Lab ID 집합과 개수, 성공 상태, 처리 수를 모두 검사한다. 빈 그래프나 일부 시나리오 누락은 성공으로 처리하지 않는다.

P02·P03·P06·P07은 실행, Node, Model, 결과 리포트를 연결하는 통합 시나리오이다. 소스 수정 없이 새 테스트를 먼저 실행하고, 실제 구현 결함이 발견되면 안전 모드에 따라 원인과 실패를 결과 문서에 기록한다.

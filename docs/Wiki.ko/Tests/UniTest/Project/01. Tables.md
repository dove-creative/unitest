# Project 자체 테스트 상태-동작 표

## 기준

공개 실행 API의 경로 탐색·재현·연속 실행과 단일 사용 수명을 검증한다. 실행 대상은 값이 1인 계산 모델이며 `Add`, `Double`, `Stop`, `Transient`의 의미는 각각 +1, ×2, 부호 반전 후 종료, +10 후 지속 불가이다. 기대 경로와 값은 별도의 작은 계산 모델에서 구한다.

`ThreadPool`과 `Inline`에 같은 표를 적용한다. 생성·실행 작업자의 경쟁 조건과 종료 대기는 기존 NUnit 테스트의 책임으로 유지한다.

## 상태-동작 표

| 상태 | - | 깊이 실행 | 지정 경로 실행 | 연속 실행 | 취소 |
| --- | --- | --- | --- | --- | --- |
| 새 프로젝트 | - | P01: 제한 깊이까지 모든 경로, **실행됨** | P02: 지정 경로만 재현, **실행됨** | P03: 지속 가능한 한 경로를 선택하며 후보 검사, **실행됨** | P10: **사용 불가** |
| 실행 완료 | - | P09: _InvalidOperationException_ | P09: _InvalidOperationException_ | P09: _InvalidOperationException_ | P09: 결과 보존, 반복 호출 허용 |
| 실행 전 프로젝트 취소 | - | P10: _InvalidOperationException_ | P10: _InvalidOperationException_ | P10: _InvalidOperationException_ | P10: 변화 없음 |
| 외부 토큰 취소됨, 프로젝트는 새 상태 | - | P08: 사용자 코드 없이 종료 | P08: 사용자 코드 없이 종료 | P08: 사용자 코드 없이 종료 | X |

## 실행 조건과 관찰

| ID | 입력 조건 | 기대 결과 |
| --- | --- | --- |
| P01 | 깊이 0, 1, 3 | 깊이 0도 첫 후보를 검사한다. 성공 경로 집합·값·실행 횟수·모델 분리·종료 분기를 독립 기준과 비교한다. |
| P02 | `Add/Double/Transient/Add`, `Double/Stop` | 각 접두 경로의 값과 이력을 검증하고, 전체 탐색에서 같은 경로의 값과 비교한다. |
| P03 | 깊이 0 및 깊이 12, seed 0·1·2 | 0은 루트만 반환한다. 양수는 매 단계 후보 4개를 검사하고 `Add`·`Double`만 확장한다. 같은 seed의 반복과 두 실행 모드의 경로가 일치한다. 선택된 경로를 별도 프로젝트에서 재현한다. |
| P04 | 빈 생성기 / 종료 Lab만 존재 | 깊이·연속 실행이 불필요한 후속 작업 없이 끝난다. |
| P05 | 첫 Lab 실패, 세 실행 진입점 | 실패와 원인 예외를 보존하고 후속 확장을 중단한다. |
| P06 | 성공·실패 형제, 실패 중단 끔 | 실패 분기는 중단하고 성공 분기의 다음 동작까지 실행한다. 실패 리포트는 실패 경로와 조상을 보존한다. |
| P07 | 첫 자식 생성 후 반복자 예외 / 없는 경로 ID | 생성기 실패는 루트 오류와 이미 생성한 자식을 보존한다. 없는 ID는 호출자에게 예외로 전달한다. |
| P08 | 사전 취소된 외부 토큰 | 생성기와 Actor를 호출하지 않으며 프로젝트는 재사용할 수 없다. |
| P09 | 세 진입점 각각으로 실행 완료 | 어떤 실행 진입점으로도 재사용할 수 없다. 취소를 반복해도 이전 결과가 바뀌지 않는다. |
| P10 | 실행 전에 프로젝트 자체를 취소 | 모든 실행 진입점을 거부하고 사용자 코드를 실행하지 않는다. |

기본 표는 15개 유효 칸이며, 입력 조건을 구체화한 시나리오는 실행 모드당 26개이다. 모드·seed·깊이는 입력 축이며 별도의 수명 상태가 아니다.
